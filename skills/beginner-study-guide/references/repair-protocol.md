# Repair Protocol｜診斷並修復舊講義

## 取得材料

優先一起讀：舊講義、原始 PPT/課本、學生標出的困惑處、題目與標準答案。若只有舊講義，就能檢查**內部**一致性與可教性，但不能聲稱已核對教師原意。

## 逐段診斷標籤

- `FACT`：事實、數學、定義或推理錯誤。
- `MODEL`：前提不同卻混在一起、符號或模型未說明切換。
- `SOURCE`：來源誤讀、額外內容未標示、考試比重無據。
- `PREREQ`：先備概念缺失、術語先用後解、教學順序倒置。
- `EXPLAIN`：抽象套話、缺失因果或中間步驟。
- `EXAMPLE`：例題不符主張、解答錯誤或未註明適用條件。

診斷時紀錄「原句/段落 → 問題類別 → 為什麼學生會困惑 → 如何修正」。不必貼滿內部標籤到最後給學生的教材。

## 修復順序

1. 先糾正 FACT/MODEL/SOURCE，不要只做語句潤飾。
2. 重排必要的 PREREQ，補上最短足夠的背景知識。
3. 對 EXPLAIN 和 EXAMPLE 改為具體的機制與可計算示例。
4. 回頭檢查修正是否影響同章其他例子、下游公式和題目答案。
5. 重新完成 `quality-gates.md` 的硬性發布門檻。

## 交付方式

- 如使用者要的是**修好的講義**：主要交付完整改正稿。最後簡短列出 3–5 個關鍵修正類別，不要讓學生閱讀冗長的檢討報告。
- 如使用者要的是**錯誤分析**：提供逐段診斷表，嚴重度與正確版本，並引原始課件作依據。
- 如學生只指出「這段很怪」：針對該段提出最小必要修正與其先備概念，而不是立即重寫整冊。

## 典型陷阱

「商品自身價格下降 → 需求增加 → 需求曲線右移」混淆了沿曲線的**需求量變動**與曲線整體移動的**需求變動**。不能用更漂亮的文字繞過它，必須改正概念，再調整例題與練習。
